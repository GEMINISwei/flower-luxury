# iPhone Safari 實機驗收

本輪實機範圍為 iPhone Safari。Chromium 的英文與 HEIC E2E 另有自動化結果；
視窗尺寸模擬與 Playwright 選檔不能證明 iPhone 的原生相機、系統選檔及下載已通過。
使用者另以 Mac Safari 響應式模式手動補驗，結果獨立記錄於下方。

## 環境與資料

在開發環境操作，使用專供驗收的員工帳號、品牌、廠商及商品。店長先從使用者管理建立員工，
業務步驟均由員工操作。照片使用自己拍攝的測試物品與[固定公開 HEIC 樣本](../../e2e/tests/fixtures/README.md)。
不需要使用私人照片，也不要把私人照片提交為測試 fixture。

手機與 Mac 在同一個可信任的區網時，可於 repo 根目錄執行：

```bash
make start lan
```

以腳本輸出的手機網址在 Safari 一般分頁開啟。這會暫時將開發環境開放至區網，
使用方式與限制見[用手機測試](../development.md#用手機測試)。原生相機與系統選檔的實際行為需在該網址上記錄；
若改用 HTTPS 測試網址，也記錄網址與協定。驗收結束後執行 `make start`，恢復只綁本機。

將 repo 內的 `e2e/tests/fixtures/IMG_2682.heic` 原樣放到 iPhone 的「檔案」，
或從[固定原檔網址](https://raw.githubusercontent.com/immich-app/test-assets/ec56cc6c1d76c45bc9615dc6ea232470a2b0a3a1/formats/heic/IMG_2682.heic)
下載後儲存到「檔案」。不要轉存為 JPEG。樣本為 iPhone 7 的 4032×3024 橫幅，內容是一組機械設備，
SHA-256 與授權記在素材說明。

## 操作步驟

### 手機原生相機拍攝後可上傳並重新開啟照片

1. 以員工登入，新增驗收商品，填妥名稱、品牌、分類及成本。
2. 點「直接拍照／Take photo」，記錄 Safari 顯示的相機或選單，以及實際使用的鏡頭。
3. 先取消拍攝：應回到原表單，既有欄位及已選照片不變，沒有多建商品。
4. 再拍一張測試物品並確認使用。應回到表單、可看到照片預覽或明確的預覽替代提示。
5. 儲存商品，確認照片可顯示；記下商品網址與 SKU，重新載入並登出再登入，照片仍可開啟。
6. 記錄相機交付的檔名與格式。原生拍攝可能交付 JPEG 或 HEIC，依實際結果記錄，不將副檔名當作格式證明。

### iPhone 系統選檔與下載保留 HEIC 原檔

1. 新增另一筆驗收商品，點「上傳／Upload」，從「檔案」選取 `IMG_2682.heic`。
2. 儲存後開啟照片：應是橫幅、沒有拉伸或裁切，位於方形顯示圖中央，上下有透明補邊。
3. 點「下載原圖／Download original」，使用 Safari 的下載流程存到「檔案」，確認檔名仍為 `IMG_2682.heic`，可開啟。
4. 將下載檔原樣傳回 Mac，使用 `shasum -a 256` 核對下載檔與 repo fixture；
   預期兩者均為 `2d9d8493696fc0054ecb4517699fec11e04bf507f1f529f6a4f293fcefdeb35e`。
   Safari 檔案資訊中的名稱或尺寸僅供輔助，不能代替 bytes／雜湊核對。
5. 另記錄若由「照片圖庫」選取時 Safari 是否轉換格式；不要把系統轉換後的 JPEG 視為已完成 HEIC 原檔驗收。

### 手機可完成商品與交易完整流程

1. 在設定的「顯示語言／Display language」選 English，重新載入後仍為英文。
2. 以員工建立品牌與臺灣廠商，建立帶照片的商品，成本填 `3100`，記錄商品網址及 SKU。
3. 新增 TWD 詢價。先輸入 `1.01`，應出現 `TWD quotes must be whole numbers`；改為 `5000` 並儲存。
4. 點 `Confirm sale` 完成成交。應顯示目前成交，成本為 3,100、金額 5,000、利潤 1,900。
   商品、詢價及照片的寫入入口不可用，仍可看照片及下載原圖。
5. 點 `Return status`，先填空白原因送出，應顯示 `This field is required`；再填明確原因完成退回。
   商品與照片恢復可操作，歷史成交保留，曾成交的詢價不可刪除。
6. 將成本改為 `3200`、原詢價改為 `6500`，再次成交。
   新快照的成本、金額、利潤應為 3,200、6,500、3,300；舊快照、退回原因仍保留。
7. 重新載入、返回列表並依 SKU 搜尋，應只有原商品一筆且為 Sold；重新開啟後照片與兩次成交仍存在。
8. 登出再登入，仍使用英文。另以錯誤密碼嘗試登入，應顯示英文 `Invalid Username or Password`。

## Mac Safari 響應式補充驗證

在 Mac Safari 開啟本機開發網址（由 `.env` 的 `SYSTEM_PORT` 決定），
使用響應式模式設定手機寬度，記錄實際 viewport。這項補驗不需 `make start lan`。

1. 依「手機可完成商品與交易完整流程」操作，確認手機版導覽、表單、確認視窗與照片不被裁切，
   無法操作的控制項或文字重疊需記錄。英文規則與金額斷言沿用相同步驟。
2. 依「iPhone 系統選檔與下載保留 HEIC 原檔」使用公開樣本；在 Mac 使用本機檔案選取器，
   下載後核對 SHA-256。這只能證明 Mac Safari 的檔案流程。
3. 桌面的「Take photo」若開啟檔案選取器，記錄該行為，不填成 iPhone 原生相機通過。
