# 產品規則

這份文件是系統產品規則的唯一來源。所有系統功能開發都在這裡維護相關規則，
新增或變更功能時同步更新對應章節，不按功能另建文件。
實作計畫、驗收條件與驗證結果寫在 commit message 或 PR 描述。
架構、開發方式與部署操作分別見 [架構](architecture.md)、[開發指南](development.md)、
[擴充指南](extending.md) 與 [維運](operations.md)。

## 系統範圍與共通操作

- 系統提供店長／員工帳號、品牌、商品、照片、廠商、詢價、成交與利潤紀錄，以及人民幣匯率設定。
  結帳批次與 AI 助手不在目前功能範圍。
- 所有登入者共用業務資料，均可操作品牌、商品、照片、廠商與詢價；管理區只開放給店長。
- 登入後直接進入商品列表。導覽依啟用模組、所在區域與權限顯示，管理區可返回商品頁。
- 支援繁體中文與英文、桌面與手機。日期時間以臺北時間顯示。
- 手機底部導覽最多保留前三個模組入口，其餘放入「更多」；順序及權限沿用原導覽。
  「更多」以底部彈窗顯示，包含頭像、暱稱與身分，溢出頁面與個人設定仍能正確標示目前位置。
- 刪除／停用、套用最新匯率與成交等需確認的操作使用站內視窗。取消、關閉或 Escape 不送出操作；
  送出期間防止重複確認，失敗訊息留在視窗，成功後更新畫面。視窗支援鍵盤操作與焦點還原。

## 帳號與權限

### 身分與管理

- 身分固定為店長與員工。使用者管理、共用註冊碼與匯率設定只開放給店長；畫面不提供角色指派或權限編輯。
- 內部沿用角色機制：店長使用系統角色 `super_admin`（權限 `*`），員工建立時不指派角色。
  原有角色 API 保留為內部管理基礎；系統角色由種子資料維護，一般 API 不能修改。
- 店長可建立員工、修改員工暱稱、停用／啟用員工及重設員工密碼。
  不能停用自己或任何店長，也不能透過後台重設店長密碼、變更店長角色或將員工指派為店長。
- 店長與員工都可在個人設定修改自己的暱稱、密碼與語系；個人設定不能變更角色或帳號啟用狀態。
- 帳號不可重複。建立帳號、註冊及重設或更換密碼時，新密碼至少 8 字元、最多 72 UTF-8 bytes。
  自行更換密碼須驗證目前密碼，登入以既有密碼驗證，不套用新密碼的最小長度。
- 停用帳號不能繼續使用系統。登出撤銷該帳號所有登入；自行更換密碼後其他裝置失效，
  目前裝置保留登入；由店長重設密碼後，該員工的所有登入失效。

### 註冊與共用註冊碼

- 登入頁提供 `/signup` 入口，註冊須填帳號、暱稱、密碼、確認密碼與共用註冊碼。
  正確註冊後立即成為啟用的店長，回登入頁登入，不自動登入；員工由店長建立。
- 第一位店長透過維運指令建立，再於 `/admin/registration` 設定共用註冊碼。
  未設定或註冊碼錯誤時拒絕註冊，公開錯誤不區分兩種原因。
- 註冊碼長度為 8 至 128 字元，僅保存 SHA-256 摘要，設定查詢只回傳是否已設定。
  更換後立即只接受新碼，服務重啟不重設；既有帳號與登入不受影響。
- 公開註冊依來源 IP 限制五分鐘最多十次，成功也計入。登入及其他限流機制見〈[限流](#限流)〉。

### 密碼救援

- 記得目前密碼時，在個人設定自行更換。
- 員工忘記密碼時，由店長在後台重設；店長不能由其他店長透過後台重設密碼。
- 沒有可登入的店長時，由維運人員使用 `make db superuser` 另建店長，操作見
  [`operations.md`](operations.md#建立店長)。系統沒有寄送密碼重設連結的功能。

## Session

### 撤銷

每位使用者在 `users` 資料表有自己的 `auth_version`，token 帶著簽發當時的值；每個需登入的請求
都會與資料庫比對，不符時拒絕。撤銷就是將版本加一，不用重啟服務或修改 `.env`：

| 觸發方式 | 作用範圍 |
|---|---|
| 使用者登出 | 該帳號所有裝置 |
| 使用者自行更換密碼 | 該帳號其他裝置；目前裝置取得新 token 繼續登入 |
| 店長重設員工密碼 | 該員工所有裝置 |
| `make db revoke-sessions` | 所有使用者，每人以自己的版本各加一 |

全員撤銷只提供維運 CLI，開發與正式環境都須確認，完成後回報影響人數。拒絕或無輸入不執行，
不提供網頁或 HTTP 入口。版本與更新時間在同一交易中更新，不變更密碼或業務資料；
已登入的裝置在下一個需驗證的請求時失效。操作見 [`operations.md`](operations.md#讓所有人登出)。

全員撤銷適用於懷疑 token 外流等緊急情況。撤銷本身是一條 UPDATE，平常的認證請求也不增加查詢；
之後所有人重新登入時，每次 bcrypt 驗證會消耗 CPU，同一來源 IP 仍受五分鐘 50 次登入限制。

撤銷擋不住 `JWT_SECRET_KEY` 外洩：拿到金鑰的人能簽發任意版本的 token，必須更換金鑰本身，見
[`operations.md`](operations.md#更換-jwt_secret_key)。新 token 不再帶全站版號 `tv`，有效舊 token
帶有這個欄位時會忽略；專案、使用者版本、用途、簽章與有效期限仍須通過驗證。

### 登入期限

沒有 refresh token，也不因持續操作而延長登入。`EXPIRE_HOURS` 是登入後必須重新登入的硬上限：
設為八小時，早上九點登入的 token 在下午五點到期。

## 限流

每層都是五分鐘滑動視窗，規則分別位於 `modules/users/router.py` 與 `modules/registration/router.py`：

| 操作 | 計數依據 | 上限 | 成功後 |
|---|---|---|---|
| 登入 | 用戶端 IP＋帳號 | 10 次 | 歸零 |
| 登入 | 用戶端 IP | 50 次 | 不歸零 |
| 自行更換密碼 | 使用者 ID | 10 次 | 歸零 |
| 公開註冊 | 用戶端 IP | 10 次 | 不歸零 |

登入同時以 IP＋帳號與 IP 計數，兼顧同辦公室的正常操作與大量嘗試不同帳號的限制；
IP 層成功不歸零，避免藉正常登入洗回額度。用戶端 IP 的轉送與單一行程限制見
[`operations.md`](operations.md#用戶端-ip-與限流)。

## 語系

前後端使用同一語系：語系存在 `locale` cookie，每個 API 請求帶 `Accept-Language`，
後端錯誤訊息跟隨 UI。字串歸屬與新增語言方式見 [`extending.md`](extending.md#語系i18n)。

## 品牌與廠商

- 品牌與廠商名稱去除首尾空白、不分大小寫去重，列表依名稱升冪排列，支援啟用／停用。
- 沒有商品引用的品牌可刪除；已有引用時改為停用，包含已刪除商品留下的引用。
  停用品牌不能用於新增商品或改選品牌，既有商品可保留原品牌。
- 廠商資料包含名稱、國家與備註。國家只提供臺灣（TW）與中國（CN），分別固定使用 TWD 與 CNY。
- 廠商一旦建立過詢價，國家永久鎖定，即使詢價後來刪除也不解除。
  沒有詢價歷史的廠商可刪除，曾有詢價者改為停用。停用後不可建立新詢價，既有詢價仍可處理。

## 商品與狀態

- 商品保存名稱、品牌、分類、型號、序號、顏色、年份、收購金額與備註；名稱、品牌、分類與收購金額必填。
  收購金額為非負整數新臺幣，最高 2,147,483,647；年份若填寫，範圍為 1 至 9999。序號可重複。
- 分類固定為鞋子、配飾、皮件、包包、帽子、衣服與其他。
- SKU 由系統產生，格式為 `LX`＋臺北日期 `YYYYMMDD`＋五碼大寫英數，建立後不可修改。
- 狀態只有「未收購」與「已出售」。新增固定為未收購，不能直接切換成已出售，須透過該商品的詢價確認成交。
  既有在庫商品與歷程已映射為未收購，保留原事件的時間、操作者及原因。
- 未收購商品可編輯、刪除與管理照片、詢價。刪除後不提供還原，詳情與照片不再可讀，成功後返回列表。
- 已出售商品鎖定欄位、照片、主圖、刪除與所有詢價寫入；只可透過獨立退回操作回到未收購，原因必填。
  退回後恢復編輯，保留詢價、歷次成交與狀態歷程。
- 狀態歷程保留建立、成交與退回事實、前後狀態、操作者 ID、當時帳號、時間與原因。
  畫面依時間由左至右呈現，重複成交與退回均保留；沒有建立紀錄時仍顯示商品建立事件。

### 列表與詳情

- 列表可依名稱／SKU／序號關鍵字、品牌、分類、狀態、顏色及年份篩選。
  桌面使用含縮圖的表格與分頁；手機使用精簡卡片，篩選由頁首開啟視窗。
- 手機捲至列表底部才續載下一批，同一商品不重複附加；失敗可重試，篩選改變時重建列表。
- 詳情顯示收購金額、狀態、分類、基本資訊、備註、照片、詢價、成交歷史與流向紀錄。
  編輯、刪除與退回操作依狀態提供；編輯與退回使用站內視窗。

## 商品照片

- 新增商品時可選取現有照片或使用手機原生相機拍照（優先後鏡頭，實際介面依裝置與瀏覽器支援），
  可連續加入、預覽及移除待上傳照片；取消選檔或拍照保留既有選取，未選照片也可建立商品。
  瀏覽器無法預覽的照片顯示提示，仍可上傳。所選照片合計沿用單次 15 MiB 上限，第一張成為主圖。
- 儲存時先建立商品再上傳照片；照片失敗保留已建立商品、編號與待傳照片，鎖定已存欄位並提示補傳。
  同頁重試不重複建立商品，可移除照片後繼續或前往詳情；離開頁面後不保留待傳原檔。
- 支援 JPEG、PNG、WebP 與 HEIC，由後端驗證實際圖片內容，不只依副檔名或 MIME 判斷。
  照片不限總張數，每次上傳的非空原檔合計不得超過 15 MiB（15 × 1024 × 1024 bytes），送出前先檢查。
- 原始檔逐位元組保存供下載，另製作固定 2560 × 2560 的無損 WebP 顯示圖。
  顯示圖套用照片方向、等比例縮放，允許放大小圖，一邊貼齊、另一邊置中補透明留白，不裁切、拉伸或去背。
- 原圖與顯示圖成對保存，下載使用原始檔名；原圖也是 WebP 時仍獨立保存。
  舊照片沒有原圖時繼續顯示並標示原圖不可用，不產生假的原圖下載。
- 第一張照片自動成為主圖。照片視窗以主圖置頂、其餘依順序直向排列，顯示圖可另開檢視。
  畫面只對其他照片提供設為主圖及刪除；要刪除目前主圖，先將其他照片設為主圖。
- 詳情的可點擊主圖與照片數量是照片入口，管理集中在照片彈窗，未收購時可由視窗右上方上傳或直接拍照。
  已出售商品只可檢視與下載。
- 每次讀取顯示圖或下載原圖都須驗證登入，禁止快取；已刪除商品的照片不可讀取或下載。
- 無效整批上傳不新增照片；寫檔失敗或交易回滾不留下新檔案，刪除照片同步清理原圖與顯示圖。

## 匯率與詢價

- 店長在 `/admin/exchange-rates` 設定匯率，定義為 1 CNY 換算的新臺幣金額，必須為有限正數。
  初始沒有預設值；設定畫面顯示及儲存時四捨五入至兩位小數，底層資料與 API 最多支援六位小數。
  設定保留最後操作者與時間，變更不回寫既有詢價或成交。
- 同商品、同廠商最多一筆詢價，重新報價修改既有紀錄，新增時排除已報價或停用廠商。
  國家決定幣別；金額必須大於零，TWD 為整數，CNY 最多兩位小數，原幣金額上限為 9,999,999,999.99。
- 詢價保存當時的國家、幣別、原幣金額、匯率、臺幣金額與備註。TWD 匯率固定為 1，
  CNY 新詢價取當時設定的匯率，未設定時拒絕新增。
- 修改金額或備註保留原匯率；只有獨立「套用最新匯率」操作更新匯率並重新計算臺幣金額。
- 後端以十進位計算，臺幣換算採四捨五入（ROUND_HALF_UP）至整數，結果不得超過 9,007,199,254,740,991。
  前端使用後端結果，不自行計算成交換匯。
- 沒有成交歷史的詢價可刪除；曾用於成交的詢價永久保留，退回後可修改原詢價並再次成交。

## 成交、利潤與退回

- 未收購商品可選定自己的詢價「確認成交」。確認視窗列出廠商、原幣金額、匯率、臺幣成交額、目前成本與利潤。
  利潤為臺幣成交額減當時成本，允許負數並明示虧損。
- 確認時檢查詢價版本與成本；其中任一已變動，須重新載入後確認。商品同時只能有一筆目前有效成交。
- 成交保存當時廠商名稱、國家、幣別、原幣金額、匯率、臺幣金額、成本、利潤、操作者與時間。
  成交、商品轉為已出售及狀態歷程必須全部成功或全部回滾。
- 退回時取消目前有效成交，保存退回時間、操作者及原因，保留原詢價與全部成交快照。
  再次成交另建快照；後續改成本、廠商名稱或匯率均不改寫歷史。
- 舊資料若有已出售商品而沒有成交快照，不補造交易；仍可依退回規則恢復未收購。
