# 詢價、成交與退回

所有登入者共用詢價與成交資料，員工可操作。沿用舊版的兩狀態流程：商品先是未收購，必須透過詢價確認成交
才成為已出售；退回後回到未收購，保留歷史成交與操作歷程。資料搬移另案處理。

## 詢價與匯率

- 同一商品與廠商最多一筆詢價，新增只能選啟用廠商。報價必須大於零且不超過 9999999999.99，最多兩位小數。
- 每筆報價自行設定匯率，未指定時預設 1；匯率須大於零、不超過 9999999999.999999，最多六位小數。
  不依廠商國家或幣別決定匯率，也不再提供全域設定或「套用最新匯率」。
- 報價乘以該筆匯率後四捨五入為整數臺幣，換算金額不超過 JavaScript 安全整數範圍。
  換算結果由後端計算，瀏覽器不能指定結果。修改報價時可以一起調整匯率，成功後增加版本。
- 建立正式詢價與廠商的 `has_quotes` 永久標記同一交易完成；即使未成交詢價全部刪除也不解除。
  新增失敗時不留下詢價或引用標記。既有正式詢價與成交的金額、匯率快照維持原值。
- 未被成交引用的詢價可刪除，曾用於成交的詢價永久保留。廠商改名不改寫已保存的成交名稱。

## 成交與退回

- 成交請求攜帶報價 ID、看到的報價版本與商品成本。後端鎖定商品後重新讀取資料，版本或成本已變更即拒絕，
  確認畫面可重新載入最新資料；不能使用其他商品的報價，也不能直接改狀態為已出售。
  商品成本儲存後先取得最新詳情再關閉編輯，後續成交使用更新後的成本。
- 成交保存廠商名稱、報價、匯率、臺幣、成本、利潤、操作者及時間快照。利潤為成交臺幣減成本，
  允許虧損，確認前明確提示。
- 成交快照、商品售出狀態與歷程一起成功或回滾。所有商品寫入鎖同一列，部分唯一索引另外保證每商品最多一筆有效成交。
- 已出售商品不可編輯／刪除、寫入照片或變更詢價，但仍可讀取資料、照片及下載原圖。
- 退回必填非空白原因，同一交易取消有效成交、記錄退回人與時間、改回未收購並新增歷程；
  任一寫入失敗都維持原有效成交及售出狀態。
- 退回後可修改商品與原詢價，再建立新的成交。過去的金額、匯率、成本、利潤與退回原因不被新成交覆寫。
- 商品詳情顯示目前有效成交的廠商名稱、臺幣金額與成交時間，使用成交快照；對應詢價標示「目前成交詢價」。
  「曾用於成交」僅表示詢價曾被引用，不代表目前成交。退回後移除目前成交摘要與標示，再成交則對應新的有效成交。
  完整成交快照與退回原因移至商品歷程頁，成交、退回及商品資料變更後同步刷新詳情與歷程。
- 商品軟刪除後，詢價與成交列表也不可讀；資料仍保留引用關係。

## 與新版架構的整合

`product_quotes` 與 `product_sales` 保留舊資料金額；歷史國家與幣別欄位只作可空的封存資料，新詢價不再填寫。
新增 migration 移除舊國家與幣別的換算約束，不改寫已發版的 migration。
ORM 查詢留在 model，詢價、成交與商品服務對外回傳 Pydantic model，寫入欄位逐一列出。
跨模組的廠商能力只經 public entry，前端使用既有型別化 API 與 UI kit，不改寫認證、Session、照片上傳或部署機制。
