# 商品暫存

商品暫存提供 LINE 圖片與文字收件、分組、整理、版本保護、逐筆審核建檔及放棄刪除。
所有登入者可從 `/product-drafts` 操作；群組設定與 LINE 接線步驟見 [LINE 商品收集](line-collection.md)。

## 收集與分組

- 來源由接線模組提供不透明的 `source_key`，同群組多人共用一條訊息流，不同群組分開。
  LINE 群組須經後台啟用，再以 `/start` 開始、`/end` 結束一批多商品收集；未開批次與本批第一張圖片前的文字略過，不保存內容。
  寫入先鎖來源列，並以部分唯一索引限制每個來源至多一個開啟批次及一筆收集中商品。
  批次狀態存入資料庫，重啟後延續；不同群組獨立，同群組多人共用。
- 第一張圖片建立暫存，連續圖片合併；一旦收到文字，下一張圖片開始下一件。
  `/end`、後台手動結束、群組停用與 Bot 退群也會結束最後一件；圖片背景下載繼續完成。
  最後一件不必等待下一件即可整理或審核。
- 原文與換行逐則保存，整理欄位另外儲存，不做 OCR；文字預填見下方說明。
  延遲事件依原始時間尋找批次與商品，歸屬明確且暫存仍存在時補入並增加版本，原始訊息依原始時間呈現。
  商品分界可能改變、時間相同無法判斷、指令順序不明或商品已審核／放棄時，只留下批次異常中繼資料，不保存該則原文或下載圖片。
  批次時間、商品時間分界與不含內容的商品鍵獨立保存，審核／放棄後仍可判斷晚到事件，不重建商品。
- 訊息可以移到同一來源的另一件暫存，移動後排在目標最後，保留原傳送時間與傳送者。
  需同時核對來源及目標版本；來源原本收到過文字的分組狀態不因搬移而倒退。
- 防重送只保存來源與外部訊息識別碼的 SHA-256 摘要，保存 30 天，再由背景工作刪除。
  摘要不含原文、圖片或傳送者；它與原始內容分開，放棄後在保存期內重送也不會重新建立資料。
  審核後另保存對應的正式商品 ID，讓訊息被移動再審核後的來源撤回也能提示人工確認；同樣到期刪除。

## 操作介面

- 列表只有收件時間、狀態、來源與「審核」操作；收件時間為第一張圖片原始傳送時間，精確到秒，依新到舊游標分頁。
  編輯欄位、補圖與補收延遲訊息不改收件時間；狀態為收集中／待審核。「審核」開啟整理畫面，正式建檔另按「審核建檔」。
- 右上角「篩選」開啟來源群組視窗，選擇後按篩選才套用；清除後套用回到全部群組。
  套用條件重置分頁，URL 保留條件，翻頁與重新整理延續；有篩選時按鈕顯示數量。
- 新 LINE 收件不再產生待歸類資料，不從文字建立空白暫存。歷史待歸類資料畫面與入口已移除，既有資料保留。
- 詳情以左右切換的單張預覽整理照片，保留設主圖、下載與刪除，不提供手動排序；
  不需要的照片直接在照片整理區刪除，缺少的照片可用「上傳照片」人工補入。
  下方原始訊息只呈現文字，在固定高度區域內上下捲動，保留換行與傳送時間，不顯示傳送者或識別碼。
  點擊單則文字即複製，
  只複製被點擊的完整原文（含換行），不合併其他訊息；失敗時提示手動複製，不會改動商品欄位。
- 使用者可自行填寫或修正 AI 預填欄位，沒有 OCR 或批次審核。可隨時儲存不完整欄位；
  審核先儲存目前內容，再以回傳版本建立正式商品，成功後前往商品詳情。
- 返回暫存列表位於內容頂端，重新載入、儲存、審核建檔與放棄位於頁首右側。
  手機列表與詳情頁首維持單排，直接顯示重整圖示及「⋯」；列表篩選與詳情的儲存、審核、放棄收進底部操作面板。
  操作中與版本衝突時沿用既有停用規則，放棄使用警示色並維持確認視窗；桌面保留文字按鈕。
  商品資訊最多兩欄，依名稱、成本、品牌／分類、型號／序號、年份／顏色、備註六列排列。
- 版本衝突時停止寫入，重新載入會保留尚未儲存的欄位，並列出最新儲存欄位供比對。
  照片完成／失敗與 LINE 新訊息不會自動覆蓋表單，按「重新載入資料」取得更新。
- 放棄與刪除照片都要確認；放棄成功回到暫存列表。手機將原文與欄位改為上下排列。

## AI 預填與暫存詢價

- 選填環境變數 `GEMINI_API_KEY`，留空時只停用 AI 預填，不影響收件、手動整理或詢價。
  API 與 worker 都需重新建立容器才會取得新金鑰，操作見[套用環境設定](../operations.md#套用-env-的變更)。
- 固定使用 Gemini 3.5 Flash-Lite，將同一件暫存商品全部文字依原始時間傳給 Gemini；
  不送照片、不做 OCR。送出的文字會由 Google 處理，請依組織資料政策配置供應商帳號。
- 收集中不解析；下一件商品開始、`/end`、後台結束、停用群組或 Bot 退群讓商品轉為待審核時，
  才將全部文字排入一次 AI 工作。同一件暫存成功或失敗後都不再呼叫，不提供手動重新預填。
  後續文字補入、撤回、移動與補充條件修改不重跑；失敗可參考原文人工整理。
  AI 工作只允許一次嘗試，已刪除或審核的暫存不會被重建。
- 固定 JSON Schema 包含商品欄位與 `vendor_info` 廠商報價陣列；所有頂層欄位都需出現，
  缺少或無關商品資訊用 `null`，沒有報價時用空陣列。後端驗證欄位、型別、可用品牌／廠商 ID 與金額。
  AI 年份只接受 1900～2100（含邊界），超出範圍時以 `null` 略過年份，保留其他解析欄位。
- `vendor_info` 每筆有 `vendor_id`、`original_amount`、`exchange_rate`。基本條件為同一行有廠商名稱中的字，
  且後接金額，名稱片段需能唯一對應清單；沒有對應文字時不猜測、不建立廠商。
  `廠商 100*4.5` 或 `廠商 100×4.5` 表示報價 100、匯率 4.5；只有價格時匯率為 1。
  同廠商取按訊息時間與行序排列的最後一筆。管理者的補充條件優先於這些基本業務判定，
  但不能變更固定 JSON 格式、可用 ID 或數值有效範圍。
- 人工修改按欄位記錄，包含刻意清空；AI 結果返回時只更新未被人工修改的欄位。
  升級前已有的整理欄位視為人工資料。畫面不自動覆寫正在編輯的表單，重新載入只更新未修改的值。
- 店長在 `/admin/draft-prefill` 的「AI 助手」頁面管理「審核預填」補充條件，可新增、刪除編號條件，
  並由頁首儲存；測試區位於同一卡片內。基礎 Prompt 與格式由系統固定，不顯示於設定畫面。
  設定只用於後續尚未開始的解析，不會重新解析既有暫存。測試預覽使用未儲存的補充條件，不修改商品。
  一次輸入上限 200,000 字元（含訊息與品牌資料）；超過時失敗，不截斷訊息。補充條件上限 10,000 字元。
- AI 廠商報價帶入商品資訊下方的詢價區，也可以手動新增、修改與刪除，同一廠商只能一筆。
  暫存保存廠商、報價、逐筆匯率與備註，未指定匯率時為 1；審核時依這筆資料建立正式詢價，
  不重新讀取全域匯率。既有人工報價不被 AI 覆寫；解析期間變更詢價清單時以人工清單為準。

## 整理與照片

- 所有登入使用者共用暫存與審核能力，不另外限制店長。
- 暫存欄位允許不完整。品牌只存選擇值，不在暫存階段建立正式商品引用；審核時再檢查品牌有效性。
- 新訊息、照片完成／失敗、手動移動、排序、主圖及欄位變更都增加版本。
  舊畫面送出的操作回覆衝突，要求重新載入。
- 圖片分成 pending、failed、ready。下載完成時重新鎖來源並確認訊息仍存在；重複完成不覆寫已成功圖片，
  已放棄或刪除的圖片不再寫檔。
- 每張圖片以內容驗證，單張最多 15 MiB，沿用既有 JPEG、PNG、WebP、HEIC 與顯示圖處理規則。
  原圖完整保存於 `/app/uploads/product_drafts/`，顯示圖另存，資料庫只保存相對路徑。
- 顯示圖沿用[商品照片](product-photos.md)的 2048 px 大圖與 128／320／640 預覽規則。
  缺少衍生圖時從原圖只補產請求的尺寸；只有原圖也可瀏覽，補產不變更暫存版本。
- 照片與原圖讀取需登入且禁止快取。dev／prod nginx 只公開照片的 `file`／`download` 讀取路徑，
  其餘讀取與寫入由 Server Component／Server Action 經內網呼叫。
- 照片整理區提供「上傳照片」，每次合計最多 15 MiB，前端與 Server Action 先檢查大小與格式，
  後端再以內容驗證，記錄操作者並增加暫存版本；
  不改變 LINE 收件時間游標或分組狀態，原檔與顯示圖沿用相同保存、回滾與清理流程。
  補圖不影響 LINE 商品分界、原始文字、既有主圖與未儲存欄位，也不重跑 AI 預填；沒有主圖時才選新增的第一張。
  上傳期間停用儲存與審核等寫入操作；失敗保留原資料，下載失敗的照片仍可直接刪除後補圖。

## 審核與放棄

- 審核需版本相符、正式商品必填欄位完整，且至少有一張照片、所有照片都 ready。
- 正式商品、照片、主圖、建立歷程與審核對照一起提交，沿用既有商品初始狀態及 SKU 規則。
  照片直接使用已處理的原圖與顯示圖，不重複辨識圖片內容。
- 審核者是正式建檔操作者；LINE 傳送者只屬於原始訊息。
  通過後刪除暫存內容，審核對照只保存商品識別、SKU、審核者與時間，重複或並發審核返回同一件商品。
- 匯入失敗回滾正式商品並清掉本次寫入的半成品，暫存可繼續修改後重試。
- 放棄採硬刪除，原文與照片資料立即不可讀；實體檔案交由同一交易排入的清理工作刪除。
  worker 停止時清理會延後，恢復後可重跑；資料庫回滾時不排入清理，也不刪除原檔。
  放棄會等待進行中的圖片補產結束，再清除原圖及全部衍生圖；放棄後的讀取不會重新補產。
- 放棄不保留商品內容或刪除歷程。30 天防重送摘要、來源收集游標、批次與商品時間分界及不含內容的待辦工作獨立保存；
  既有備份依備份保存策略淘汰，系統不代替 LINE 刪除聊天訊息。
