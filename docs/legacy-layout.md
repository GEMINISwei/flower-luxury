## 視覺驗收紀錄

- 使用獨立 Next.js 預覽與合成資料, 不連接真實資料庫。
- 桌面 1280px、平板 820px、手機 390px: 商品列表表格／卡片、長名稱、空清單與分頁通過。
- 商品詳情照片／資料分欄、照片操作及新增商品雙欄／單欄表單通過。
- 品牌與廠商手機卡片、登入／註冊品牌卡片、設定頁頁首與底部導覽通過。
- 檢查中英文文案; 手機與平板的頁面沒有橫向溢出。較窄的桌面表格可在卡片內橫向捲動。
- 保留目前的彈出視窗編輯流程與詢價／成交功能; 不新增舊版專屬功能。
- 舊專案 CSS 引用的 `marble-cream.png` 並不存在於舊專案, 登入背景沿用奶油色漸層。

## 商品詳情與兩狀態流程驗收

| 驗收條件 | 測試名稱 |
| --- | --- |
| 只保留未收購、已出售；未收購可編輯／刪除，已出售只可退回。 | `未收購可編輯刪除，已出售只允許退回`、`test_status_transitions_follow_workflow` |
| 詢價成交直接設為已出售並留下成交快照，退回至未收購且必填原因，再次成交保留歷史。 | `test_sale_snapshots_profit_and_locks_all_mutations`、`test_return_and_resale_preserve_snapshots_and_quote`、`test_return_requires_reason` |
| 既有在庫商品與歷程映射為未收購，歷程的操作者、原因與時間保留；資料庫拒絕再寫在庫。 | `test_two_status_migration_preserves_history_and_rejects_in_stock` |
| 圖片預設主圖，點選縮圖更換大圖；刪除選取照片後回到有效主圖，沒有照片時顯示佔位。 | `圖庫預設主圖並保留縮圖排序`、`圖庫選取失效時回到主圖，空圖庫回傳空值` |
| 狀態履歷依時間從左到右，保留重複成交／退回、日期、操作者與原因，空歷程仍顯示建立事件。 | `流向依時間排列並保留成交退回原因`、`空歷程以建立事件顯示未收購` |
| 詳情採大圖＋橫向縮圖、上方成本、基本資訊每行一欄；右上角編輯、刪除、已出售才出現退回，編輯與退回均使用 Modal。 | `商品詳情參考圖桌面與手機視覺驗收` |

本次使用者明確要求移除在庫，原先三狀態的測試定義在實作前一併調整為兩狀態；實作開始後測試鎖定。

### 本輪驗證紀錄

- 1440px 桌面、390px 與 320px 手機：大圖／縮圖列、上方成本、逐行資訊、空照片佔位與頁首圖示均已檢查。
- 點選第二張縮圖後，大圖連結與圖片來源同步更新；編輯、刪除與退回視窗正常開啟，取消不送出操作。
- 已出售才顯示退回；原編輯／刪除維持售出鎖定。退回原因只有空白會顯示必填錯誤。
- 中英文流向記錄可由左至右閱讀；手機僅在記錄區左右捲動，整頁無橫向溢出。
- 合成資料預覽未連接真實資料庫；成交、退回及舊資料遷移的實際寫入由拋棄式 PostgreSQL 整合測試驗證。
- 新增 migration `29e7062acabd`，將商品與歷程中的 `in_stock` 映射為 `not_acquired`，保留原事件。downgrade 僅放寬約束，無法還原合併前各筆狀態。
