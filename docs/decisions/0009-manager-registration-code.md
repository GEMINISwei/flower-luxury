# 0009. 以共用註冊碼開放店長註冊，第一位店長由 CLI 建立

狀態：採用（2026-10-27）

取代：[0002](0002-no-web-signup.md)

## 背景

本專案沿用既有系統的店長／員工流程。店長需要在不取得主機 shell 的情況下，讓持有共用註冊碼的人
自行建立店長帳號；員工仍由店長建立。模板禁止網頁建立超級管理者的產品限制不符合這個需求。

## 決定

- 第一位店長透過 `make db superuser` 建立。註冊碼未設定時，公開註冊一律拒絕。
- 只有店長能設定或更換共用註冊碼；設定後，持有有效碼者可從 `/signup` 建立啟用的店長帳號。
- 註冊碼只保存 SHA-256 摘要，設定查詢只回傳是否已設定；換碼立即使舊碼失效，不影響既有帳號。
- 註冊成功後回到登入流程，不自動登入。公開註冊依 IP 限制五分鐘十次，成功也計入。
- 店長使用既有 `super_admin` 系統角色，員工不指派角色。畫面不提供角色指派或角色權限編輯。
- 後台只開放店長；不得停用自己或任何店長，不得經一般帳號 API 指派店長角色或重設店長密碼。
- CLI 入口保留在 `users/superuser.py`，共用建帳邏輯由 users 擁有，registration 只透過 public entry 呼叫。
- 保留新版的模組邊界、連線管理、密碼併發保護、Session、限流與 migrate seed 流程。

## 後果

- 註冊碼等同建立店長的授權憑證，店長需要妥善保管；它不是建立員工的邀請碼。
- 第一位店長仍需維運人員協助建立；店長失聯時也可透過同一 CLI 救援。
- 沒有 email 驗證、寄信重設密碼或多店資料隔離。所有登入者共用業務資料。
- 註冊設定保留舊版資料表與欄位，既有資料搬移另外處理。
