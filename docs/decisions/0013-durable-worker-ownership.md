# 0013. 背景工作以 worker 心跳與每次領取 token 保護執行權

狀態：採用（2026-11-02）

## 背景

背景工作已依 [0006](0006-postgres-job-queue.md) 使用獨立容器與自製 PostgreSQL 佇列。
固定任務租約將故障偵測與工作時間上限綁在一起；只有本機心跳檔也無法告訴其他 worker
哪些工作需要回收。工作數量增加後，需要同一套去重、死信、排程與安全重啟規則。

## 決定

- 每次啟動產生新的 worker ID，在資料庫維持心跳；失聯後不可恢復舊 ID 的執行權。
- 領取與失聯回收鎖定同一筆 worker 紀錄，每次領取仍產生唯一 token。
- 完成與失敗更新同時驗證 worker 存活、工作狀態與 token；失去執行權則回滾業務寫入。
- 成功紀錄保留以支援去重，但立即清空 payload；錯誤只保存安全分類。
- 工作與業務資料同交易，通知由 PostgreSQL 在提交後送出；保底輪詢處理漏通知與延遲工作。
- 不同佇列使用獨立且有限的消費迴圈；關機停止領新工作並限時等待完成。

## 後果

- 故障回收時間不依賴任務 timeout，長工作仍須自己的執行時間上限。
- 去重鍵的保留時間決定通用去重範圍；業務事件仍由模組的 receipt 保護。
- token 保護資料庫提交，不能保證外部 API 只被呼叫一次；未知結果須由模組決定重試界線。
- 佇列與 worker 的競爭條件需要整合測試；擴充依然不增加 API 的 uvicorn workers。

使用方式見 [背景工作](../extending/background-jobs.md)。
