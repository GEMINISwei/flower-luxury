# 0006. 分開執行後端測試，合併覆蓋率後維持原門檻

狀態：採用（2026-11-09）

## 背景

本專案的後端 74% 門檻原本由完整單元與資料庫整合測試共同驗證。CI 改為平行分組後，
純單元的覆蓋率為 71.30%；沿用來源只在單元 job 判定的方式，會把原本由真實資料庫守住的行為算成未測。

## 決定

- `api-test` 與 `api-integration` 各執行自己的測試，分別產生覆蓋率資料。
- 每組收集時不單獨判定比例；`api-coverage` 必須取得兩份資料，合併後用原有 74% 門檻判定。
- `ci-gate` 等待 `api-coverage`；缺少資料、合併失敗或比例未達門檻都不能通過完整 CI。
- 純 Markdown PR 沿用 docs 模式，合併到 main 時仍執行完整測試與覆蓋率判定。

## 後果

測試仍各跑一次且可以平行，不降低原有門檻，也不為比例補重複 mock 測試。
代價是 CI 多一次 artifact 傳遞與合併；這是本專案對來源檢查流程的調整。
